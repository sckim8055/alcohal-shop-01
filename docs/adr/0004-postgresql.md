# 0004. DB 를 PostgreSQL 16 으로 바꾼다

날짜: 2026-11-25

## 결정

- DB 는 PostgreSQL 16 하나만 지원한다. H2(파일 DB)와 MySQL 8 기준은 없앤다.
- 개발 PC 에서는 이미 떠 있는 PostgreSQL 16(`localhost:5433`, 재고관리 프로젝트와 같은 서버)을 쓰고, DB 와 계정은 따로 둔다: 계정 `sool`, 개발용 `sool`, 테스트용 `sool_test`.
- 테스트도 H2 가 아니라 PostgreSQL 에서 돌린다. 개발·테스트·운영이 같은 DB 여야 "테스트는 통과했는데 운영에서 깨지는" 일이 줄어든다.
- 암호는 저장소에 적지 않는다. 환경 변수 `SOOL_DB_PASSWORD`(PC 에서는 `db.local.bat`, `.gitignore` 대상)로 넘긴다.
- 운영 자료가 없으므로 V1~V7 스크립트를 새 파일로 덧붙이지 않고 그 자리에서 PostgreSQL 문법으로 고쳤다. 이번 한 번만의 예외이고, 앞으로는 다시 새 파일로만 바꾼다.

## 이유

- 아직 개발 단계라 옮길 자료가 없다. 미룰수록 MySQL 문법 스크립트가 쌓이고, 운영 뒤에는 자료 이전과 중단이 따른다.
- 결제·정산과 여러 몰 운영에 쓸 기능(엄격한 자료 규칙, 행 단위 접근 제한)이 PostgreSQL 쪽에 있다.

## 바꾼 것

- 스크립트: `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`, `DATETIME(6)` → `TIMESTAMP(6)`, `MEDIUMTEXT` → `TEXT`, 기본 시각은 UTC 로.
- 조회문: 형식을 모르는 NULL 매개변수 3곳에 `CAST`, 평점순 정렬에 `NULLS LAST`, 이름 검색 4곳을 `ILIKE` 로.
- 빌드: H2 를 빼고 `org.postgresql:postgresql`, `org.flywaydb:flyway-database-postgresql` 을 넣었다.

## 잃은 것과 남은 것

- "폴더만 복사하면 도는" 휴대용 구성이 아니다. PostgreSQL 서버가 떠 있어야 서버와 테스트가 돈다.
- 재고관리 프로젝트와 서버를 같이 쓰므로 그 서버를 내리거나 올리면 술장터도 같이 멈춘다. 운영에서는 따로 둔다.
- 기존 H2 자료(`server/data/sool.mv.db`)는 옮기지 않는다. 시범 데이터뿐이라 새로 넣으면 된다.
- 테넌트(몰)별 행 단위 접근 제한은 아직 쓰지 않는다. 여러 몰을 열 때 정한다.
